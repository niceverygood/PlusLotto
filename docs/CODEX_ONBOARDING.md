## 0. 시작하기 전에 반드시 읽는다 (이 순서로)

1. `CLAUDE.md` — **모든 결정의 단일 기준**. 기술 스택, 디자인 토큰, 폴더 규칙, 완료 기준(DoD)이 전부 여기 있다. 여기서 벗어나는 판단을 하지 않는다.
2. `docs/MIGRATION_LEGACY_SITES.md` — 레거시 이관 매핑표. §0.4(4사 코드대응표), §1(user→members), §2(코드 매핑), §3(payment→payments), §5.6(적재 도구)을 정독한다.
3. `docs/DECISIONS.md` 의 **D176 · D177 · D178 · D179** — 8/31 이관 사고와 원복, 발송 재개, 9/7 문자 재발송 경로. **D177 은 815 적재를 통째로 원복한 기록이다. 지금 운영 DB에 레거시 회원은 0명이다.**
4. `docs/ASSUMPTIONS.md` — 추정으로 정한 것들. 여기 적힌 항목은 마음대로 확정하지 않는다.
5. `docs/LEGACY_VENDOR_REQUESTS.md` — 기존 업체에 요청한/받은 자료 목록.

읽고 나서, **당신이 이해한 현재 상태를 5줄 이내로 요약해 먼저 보고한다.** 내가 확인해 준 뒤에 코드를 건드린다.

## 1. 이 프로젝트가 어떤 것인지

- 로또 번호 추천 서비스의 **아웃바운드 텔레마케팅 CRM 백오피스**다. 일반 사용자 프론트가 아니라 내부 운영툴이다.
- Vite + React 18 + TypeScript(strict) / Tailwind(토큰만) / TanStack Query v5 · Table v8 / Supabase(Auth·Postgres·RLS) / zustand / recharts / Vercel.
- **서버 상태는 전부 TanStack Query 경유.** 컴포넌트에서 직접 fetch 금지. 데이터 접근은 `features/*/api.ts` 훅으로만.
- **데이터 경로가 두 갈래다**: `dataSource === 'supabase'`(→ `features/*/supa.ts`)와 mock(`readDb()`/`mutateDb()`). **쓰기를 추가하면 반드시 양쪽 모두에 반영한다.** 한쪽만 고치면 로컬에서는 되는데 운영에서 안 되거나 그 반대가 된다.
- **`api/*.ts`(Vercel 함수)는 `src/` 를 import 할 수 없다.** 런타임이 상대 경로를 해석하지 못한다. 필요한 로직은 그 파일 안에 복사하고, 원본 위치를 주석으로 남긴다(`api/weekly-reco.ts`, `api/resend-failed-sms.ts` 가 그 예다).
- UI 텍스트는 한국어. 색·간격·라운드는 `design-system/tokens.css` 토큰과 Tailwind 유틸만 쓴다. 임의 hex/px 금지.

## 2. 이번 작업 — 레거시 4사 이관

기존 전산업체가 운영하던 4개 사이트를 우리 통합 전산으로 옮긴다. 6개 사이트가 **완전히 동일한 벤더 스키마**를 쓴다(`user` 152컬럼 · `payment` 113컬럼 · `userMemo` · `pushSms` · `gameBettingNlotto`). 그래서 변환기 하나가 4사 전부를 처리한다.

| 사이트 | DB 키 | 상태 |
|---|---|---|
| 815로또 | `lotto815` | 자료 수령 완료. **8/31 적재했다가 D177 로 전량 원복함** — 다시 넣어야 한다 |
| 일행로또 | `cplotto` | 자료 수령 완료. 무결성 검증까지 끝나고 대기 중 |
| 인포로또 | `infolotto` | 자료 수령 완료 |
| 프리미엄로또 | (키 미정) | **원본 덤프 미수령. 등급 대응표도 없다** |

주의할 점 두 가지가 실제로 사고를 냈다.

- **일행로또의 DB 이름은 `cplotto`** 다. 도메인·상호와 달라 헷갈린다.
- **일행로또는 등급 이름이 우리와 겹치는데 뜻이 다르다.** 일행의 「골드」·「골드플러스」 → 우리 **실버**(`goldp`), 일행의 「VIP」 → 우리 **골드**(`vip`). 표는 `docs/MIGRATION_LEGACY_SITES.md` §0.4 에 있고, 이미 현장 승인이 끝났다. **임의로 다시 매핑하지 않는다.**

작업 순서는 현장(정의현 차장)이 정한 우선순위를 따른다. 지정이 없으면 **815 → 인포 → 일행** 순으로 진행하고, 프리미엄은 자료가 오면 착수한다.

## 3. 적재 도구 — 새로 만들지 말고 이걸 쓴다

`scripts/load-legacy-site.py` 가 이미 있다. 검증된 도구이므로 **새 스크립트를 짜지 말고 이걸 확장한다.**

```bash
# 1) DB에 접속하지 않고 무엇이 들어갈지만 본다
python3 scripts/load-legacy-site.py --site lotto815 --archive ./815.zip --dry-run

# 2) DB를 읽기만 해서 기존 데이터와 대조한다
python3 scripts/load-legacy-site.py --site lotto815 --archive ./815.zip --plan

# 3) 시범 적재 — 반드시 소량으로 먼저 한다
python3 scripts/load-legacy-site.py --site lotto815 --archive ./815.zip --limit 100 --apply

# 4) 전체 적재
python3 scripts/load-legacy-site.py --site lotto815 --archive ./815.zip --apply
```

- 환경변수: `VITE_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`
- **`--dry-run` → `--plan` → `--limit 100 --apply` → `--apply` 순서를 건너뛰지 않는다.** 8/31에 이 순서를 지켜서 성능 회귀를 시범 단계에서 잡았다.
- 도구에는 테스트가 있다(`scripts/test_load_legacy_site.py`, 14개). 도구를 고치면 **테스트를 먼저 고치거나 추가한다.**
- 덤프는 한 줄에 한 행이 아니다. 값 안에 줄바꿈·괄호·쉼표가 들어 있어서 **줄 단위로 자르면 깨진다.** 따옴표 상태를 추적하는 튜플 스캐너를 써야 하고, 이미 도구에 구현돼 있다.
- 프리미엄로또를 추가하려면 `GRADE_BY_SITE`(`scripts/load-legacy-site.py`)와 `LEGACY_SITES`(`src/lib/legacySites.ts`) 양쪽에 키를 넣어야 한다. **등급 대응은 현장 승인 없이 추정하지 않는다.**

## 4. 절대 하면 안 되는 것 (전부 실제로 사고가 났던 항목이다)

1. **회원 등급으로 조합 세트수를 유추하지 않는다.** 회원별 `weekly_reco_count` 가 우선이다. 등급에서 역산하면 매니아 회원 991명의 조합이 절반으로 줄어든다.
2. **`weekly_reco_day`(조합 발송요일)에 기본값을 넣지 않는다.** 비어 있으면 비운 채로 둔다. 기본값을 넣으면 수천 명이 같은 요일에 몰려 한 번에 발송된다.
3. **레거시 적재 회원은 `meta.reco_paused = true` 로 들어가야 한다.** 도구가 이미 그렇게 넣는다(`load-legacy-site.py:336`). 이 값을 빼거나 false 로 바꾸지 않는다. 검수 전에 대량 문자가 나가는 것을 막는 최후 방어선이다.
4. **적재 전에 반드시 원본과 삭제 대상을 백업한다.** D177 에서 원복이 가능했던 유일한 이유다. 배치 키(`--batch-id`)를 반드시 지정하고, 그 키로만 되돌릴 수 있게 한다.
5. **되돌릴 수 없는 대량 쓰기·삭제는 실행 전에 나에게 확인받는다.** 건수·금액·연결행을 먼저 세어서 보고하고, 승인 뒤에 실행한다.
6. **전역 발송 스위치(`weekly_free_reco.enabled`, `paid_sms`)를 임의로 끄거나 켜지 않는다.** 현재 둘 다 켜져 있다(D178). 변경은 현장 승인 사항이다.
7. **테스트를 건너뛰거나 비활성화해서 통과시키지 않는다.**

## 5. 작업하는 방법

- 작은 단위로 커밋한다. 커밋 메시지는 한국어로, **무엇을 왜 바꿨는지** 쓴다.
- 코드를 바꿨으면 `npm run build`(= `tsc --noEmit && vite build`)를 돌려 통과시키고 나서 푸시한다.
- 파이썬 도구를 바꿨으면 `python3 -m pytest scripts/test_load_legacy_site.py` 를 돌린다.
- 새로 정한 규칙·발견한 사실은 `docs/DECISIONS.md` 에 항목을 추가한다. 추정으로 정한 것은 `docs/ASSUMPTIONS.md` 에 `[화면] / 추정내용 / 근거 / 확인필요` 형식으로 남기고 코드에 `// TODO(live-verify): ...` 주석을 단다.
- **모르는 것은 추측해서 진행하지 말고 물어본다.** 특히 등급 대응, 이관 범위, 전환 시점(cutover), 발송 정책은 전부 현장 결정 사항이다.

## 6. 보고 형식

작업이 끝나면 두 가지를 준다.

1. **개발자용 요약** — 무엇을 바꿨는지, 어떻게 검증했는지, 남은 것은 무엇인지.
2. **현장 카톡용 메시지** — 수신자는 비개발자(정의현 차장 등 운영진)다. 코드·파일명·함수명 같은 개발 용어를 빼고, **화면과 기능 이름, 눈에 보이는 변화** 중심으로 쓴다. 존댓말, 항목별 번호. 각 항목에 (a) 무엇이 어떻게 바뀌었는지 (b) **지금 반영(배포)된 상태인지 아닌지** (c) 현장에서 확인할 것이 있으면 그 방법을 쓴다. 코드블록 없이 바로 복사해 보낼 수 있는 형태로.
