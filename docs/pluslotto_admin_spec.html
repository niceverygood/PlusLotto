Overview

이 시스템은 무엇인가

「플러스로또」는 단순 로또 사이트가 아니라, 유입된 리드를 영업조직(실장·팀장·담당자)이 전화로 전환시키는 아웃바운드 텔레마케팅 CRM 백오피스입니다. 일반 사용자용 프론트가 아닌 내부 운영툴이며, 약 15만 명 규모의 회원 DB를 다룹니다.

핵심 운영 흐름

유입
유입코드/분류 → 담당 배정
수동/자동할당 → 아웃콜
미아웃콜 관리 → 전환
무료→유료등급 → 결제
다중 PG → 번호발송
SMS 스케줄 → 매출귀속
담당/팀장

문서 사용법

  • 01 정보구조는 "무엇을 만드는가" — 전체 화면 지도, 권한 모델, 라우트, 데이터 엔티티.
  • 02–03 디자인 시스템 / 컴포넌트는 "어떻게 보이는가" — 아래 모든 컬러·컴포넌트는 실제 렌더링된 결과물이며, 그대로 CSS 토큰/Tailwind config로 옮깁니다.
  • 04 구현은 Claude Code 투입용 — 폴더 구조, 화면 패턴, 우선순위.
이 문서는 스크린샷 37장(실제 렌더)을 근거로 작성됐습니다. 나머지 19장은 원본 사이트가 file not found로 응답해 비어 있었고, 해당 화면들은 미확인 화면 섹션에 라이브 재캡처 대상으로 정리했습니다. 백엔드 로직(PG 연동·문자 스케줄러·자동배정·권한)은 라이브 사이트 검증 단계에서 확정합니다.

내비게이션 모델

좌측 고정 사이드바 + 상단 바 + 콘텐츠 영역의 3분할 셸. 개선 포인트는 대분류 그룹핑과 접이식 사이드바, 그리고 알림 카운트 뱃지의 의미 명확화입니다.

원본 구조의 문제

  • 13개 메뉴가 그룹 없이 평면 나열 → 스캔 비용 높음
  • '메인'이 대시보드가 아니라 목록으로 빠짐
  • [관]/[실] 프리픽스가 라벨 안에 섞여 가독성 저하
  • 카운트 뱃지(이용자 385, 결제 1)의 기준 불명확

재설계 방향

  • 3개 논리 그룹: 운영 / 고객·세일즈 / 시스템
  • 프리픽스 제거 → 역할에 따라 메뉴 자체를 노출/숨김
  • active 상태: 좌측 3px 인디케이터 + 배경 틴트
  • 카운트 뱃지 = "내가 처리할 신규/대기 건수"로 통일
  • 접이식(아이콘 only) 토글로 데이터 영역 극대화

실제 사이드바 렌더는 앱 셸 컴포넌트 참고.

라우트 구조

26개 이용자 세그먼트는 별도 페이지가 아니라 하나의 리스트 + 저장된 필터 뷰(query param)로 통합합니다. 코드 중복을 없애고 유지보수를 단순화하는 핵심 개선입니다.

페이지 템플릿 분류

56개 화면은 결국 5개 템플릿의 반복입니다. 템플릿을 표준화하면 화면 90%가 조립으로 끝납니다.

A · 리스트형

필터 + 데이터 테이블 + 벌크액션 + 페이지네이션. 이용자·결제·매출·로그·베팅·로또 = 약 45개 화면.

B · 폼형

섹션 그룹 + label/input 행. 사이트설정·이용약관·로또고정제외.

C · 대시보드형

KPI 카드 + 차트 + 처리 대기 리스트. 메인(신규)·리포트.

D · 통계형

기간 필터 + 차트 + 요약 테이블. 가입·결제·유입 통계.

E · 상세/편집

drawer/모달. 이용자 상세·결제 상세·문의 답변.

게시판형

공지·이벤트·FAQ = 리스트형(A)의 경량 변형.

02 · Design System

디자인 원칙

① 운영 효율 우선

하루 수백 건을 처리하는 도구. 멋보다 스캔 속도·클릭 수 최소화·밀도가 먼저. 단, 밀도가 혼란이 되지 않도록 정돈.

② 데이터 가독성

숫자는 tabular figures로 자리 정렬, 본문 14px로 키워 원본의 8~9px 가독성 문제 해결.

③ 역할별 명확성

등급·상태를 일관된 컬러 토큰으로 코드화 → 범례 없이도 한눈에 구분.

④ 차분한 네이비

원본의 네이비 아이덴티티 계승, 액션은 단일 블루, 능동 행위(문자·아웃콜)는 앰버로 신호.

폴더 구조 (제안)

src/ ├─ app/ │ ├─ routes.tsx # 라우트 + 역할 가드 │ └─ providers.tsx # Supabase, Query, Theme ├─ design-system/ # 이 문서의 토큰이 사는 곳 │ ├─ tokens.css # CSS 변수 (위 컬러/스페이싱 전부) │ ├─ tailwind.config.ts # 토큰 → Tailwind 매핑 │ └─ components/ # Button, Badge, DataTable, FilterBar … ├─ features/ │ ├─ members/ # 이용자 + 26 saved views │ │ ├─ views.ts # 26개 필터 프리셋 정의 │ │ ├─ MembersPage.tsx │ │ └─ MemberDrawer.tsx │ ├─ payments/ revenue/ community/ support/ │ ├─ admins/ logs/ stats/ │ ├─ lotto/ bets/ settings/ │ └─ dashboard/ ├─ lib/ │ ├─ supabase.ts # client + 타입 │ ├─ rls/ # 역할별 정책 메모 │ └─ format.ts # 금액·전화·일시 포매터(tnum) └─ types/ # DB 엔티티 타입 (위 데이터 모델)
핵심 원칙: 토큰은 design-system/tokens.css 한 곳에서만 정의 → 색 하나 바꾸면 전 화면 반영. 26개 이용자 세그먼트는 views.ts의 필터 프리셋 배열로, 화면 코드는 1개만 존재.
