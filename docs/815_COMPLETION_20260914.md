# 815 잔여 이관 — 사이트별 계약 보존

## 변경 범위

잔여 전화번호 충돌 회원 2,666명을 원본 회원키마다 별도 815 계약으로 보존하기 위한 변경이다. 기존 플러스 회원의 등급·기간·전화번호·비밀번호·결제 내역은 병합하거나 덮어쓰지 않는다. 역할·연락처 확인이 필요한 계정은 이 범위에 넣지 않는다.

- 문자 요청은 회원 ID를 전달하고 서버에서 직원 권한, 실제 회원 번호와 출처를 확인한다. 전화가 같은 다른 사이트의 보류 상태가 기존 회원 발송에 적용되지 않는다. 회원 ID 없는 구형 요청은 기존 번호 전체 보류를 유지하므로 직원은 배포 후 화면을 새로고침한다.
- 두 고객 로그인 화면에 가입 서비스 선택을 추가했다. 기존 사이트 없는 캐시는 폐기한다. 플러스는 해당 사이트 안에서 기존 최신 가입자 선택·비밀번호 규칙을 유지한다. 다른 사이트의 모호한 동일 번호 계정은 임의 선택하지 않는다. 기존 플러스의 동일 번호 유효 계정이 복수인 경우 1개 번호가 확인되었으며 데이터는 변경하지 않는다.
- 서비스 전용 원자 이관 함수는 원본 키·결제·동의·발송 보류·계정 플래그를 검사한다. 해당 트랜잭션에서만 중복 등록 트리거가 별도 815 행을 허용한다. 일반 중복 등록은 같은 사이트만 대조하고, 815 일반 신규가입은 허용하지 않는다.
- 과거 문자·당첨 이력은 읽기 전용 이력 테이블에 저장하며 발송·조합·예약을 재생하지 않는다.

## 적용 및 검증 순서

1. 합성 데이터로 역할·전화 형식·계약 선택·원자 롤백·재실행 보호를 검사한다.
2. DB 함수 원본 정의와 현재 배포를 보존하고 DB 변경·서버·화면 버전을 함께 배포한다.
3. 운영 API의 check_only로 대상 회원·출처·보류를 확인한다. 실제 문자 요청은 하지 않는다.
4. 고정 원본 해시와 명세를 대조한 10명 시범 이관 후, 기존 회원·결제 전체 행과 발송 보류를 다시 대조한다.
5. 남은 배치와 과거 이력을 적용하고 고정 명세·현재 행·원본 건수·금액·필드 지문을 독립 대조한다.

이 문서는 실행 절차다. 배포·적재 완료 여부와 수치는 저장소 밖 실행 영수증 및 당일 결과 문서로 확인한다. 고객 원문·비밀번호·확인 명단·인증정보는 저장소에 넣지 않는다.

## 복구 원칙

시범 이관 전에는 기존 함수 정의와 이전 애플리케이션 버전으로 복구할 수 있다. 동일 번호의 별도 계약이 적재된 후에는 전화번호만으로 계정을 고르던 구형 로그인·발송 버전으로 되돌리지 않는다. 문제가 발견되면 추가 배치를 중단하고, 이관 보류와 사이트 분리는 유지한 채 수정한다. 통신 결과가 불명확한 배치는 영속 시도표식과 실제 행을 확인하며 재삽입하지 않는다.

## 아직 필요한 업무 확인

최종 확인표 179명(미이관 확인 대상 108명 + 기이관 시범 계정 확인 71명)의 분류·연락처, 담당자 인계 기준, 8월 31일 이후 직원 수작업 변경분과 최종 확인 시각은 별도 확정 대상이다. 문자·추천 보류 해제와 구전산 종료는 이번 데이터 적재 성공만으로 실행하지 않는다.
