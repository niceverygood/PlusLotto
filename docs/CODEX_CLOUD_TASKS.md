## 2. 실제 적재는 로컬에서 (클라우드 아님)

작업 B 로 코드가 준비되면, 적재는 원본 덤프가 있는 로컬에서 사람이 지켜보며 한다.
**순서를 건너뛰지 않는다.** 8/31에 이 순서를 지켜서 시범 단계에서 성능 회귀를 잡았다.

```bash
export VITE_SUPABASE_URL=...
export SUPABASE_SERVICE_ROLE_KEY=...

# ① DB 접속 없이 무엇이 들어갈지만 본다
python3 scripts/load-legacy-site.py --site lotto815 --archive ./815.zip --dry-run

# ② DB 를 읽기만 해서 기존 데이터와 대조한다
python3 scripts/load-legacy-site.py --site lotto815 --archive ./815.zip --plan

# ③ 시범 적재 — 반드시 소량으로 먼저 한다. 여기서 멈추고 결과를 확인한다.
python3 scripts/load-legacy-site.py --site lotto815 --archive ./815.zip \
  --limit 100 --batch-id lotto815-20260908 --apply

# ④ 전체 적재
python3 scripts/load-legacy-site.py --site lotto815 --archive ./815.zip \
  --batch-id lotto815-20260908 --apply
```

**적재 전 반드시**: 배치 키(`--batch-id`)를 지정한다. D177 에서 전량 원복이 가능했던 유일한 이유가
이 키였다. 그리고 삭제 대상 스냅샷을 저장소 밖에 백업한다.

**적재 후 반드시**: 위 작업 B 4번의 검증 SQL 로 대조하고, 결과를 `docs/DECISIONS.md` 에 기록한다.
검수 전에는 전역 발송 스위치와 배치 일시정지를 해제하지 않는다.
