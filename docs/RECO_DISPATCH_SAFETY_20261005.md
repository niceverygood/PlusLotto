# 추천번호 발급·문자 동시 실행 방지

자동 크론과 수동 발급이 같은 회원·회차를 동시에 읽으면 중복 문자와 오래된 회원정보 덮어쓰기가 가능했다. 최초 발급 경로를 `reco_issue_claim`/`reco_issue_finish`로 통합한다.

## 동작

- 회원·회차 고유 선점과 조합 저장, 미확정 SMS 기록을 한 트랜잭션으로 처리한 뒤 업체를 호출한다. 동일 전화라도 회원 ID가 다른 계약은 각각 유지한다.
- 행 잠금 후 현재 상태·보류·만료·요일·조합 수·브랜드·발신번호·운영자 권한을 확인한다. 전체 meta 및 등급·번호의 예상값이 달라지면 발급하지 않는다. `weekly_recos` 키만 갱신한다.
- 기존 회차가 이력 어느 위치에 있든, 또는 영속 선점이 있으면 재발급하지 않는다. 실패·응답불명·기록 실패·발급만 한 상태도 자동 재선점하지 않는다. 삭제 기능으로 표시 이력을 지워도 선점 기록은 남는다.
- D51/D55 현행 권한(admin/manager/leader 전체, rep 본인 담당)을 유지한다. 신규 권한을 부여하지 않는다.
- 기존 전체 `GET` 크론과 `audit=1` 대조는 유지한다. `GET dryRun=1`과 `POST dryRun:true`는 조회만 한다. `audit=1`은 감사 로그를 쓰므로 읽기 전용 점검에 사용하지 않는다.
- 정확한 명단 실행은 `POST`의 중복 없는 `memberIds` 1~50명과 선택적 `expectedRound`를 사용한다. 잘못된 범위·옵션이나 전체 `force=1`은 전체 실행으로 폴백하지 않고 거절한다. 명단 실행은 자동으로 전체 크론을 이어 호출하지 않는다.
- 수동 발급은 인증된 운영자가 정확한 1명을 지정한다. 명시 조합 수 1~100은 수동 발급에만 적용하며 회원의 자동발송 설정을 바꾸지 않는다. 일반 자동 발급의 안전 상한은 1,000개다.
- 화면은 응답불명이나 영수증 저장 실패를 성공으로 표시하지 않는다. 오류 때도 발급·문자 내역을 새로 조회한다.

## 적용 순서와 경계

DB 마이그레이션을 트랜잭션으로 적용하고 권한·함수·빈 선점표를 확인한 후 API/화면을 배포한다. 운영 별칭과 배포 커밋, 정확한 명단 dryRun의 쓰기 0, 기존 보류 유지 등을 별도로 확인한다.

이 변경은 회원 보류를 해제하거나 실제 문자를 발송하지 않는다. 이관 첫 발송은 실제 구전산 중단, 명확한 시험 명단, 업체 접수, 현장 수신 확인 조건을 따라 진행한다. 회원·회차 선점은 새 서버 경로에 적용되므로 운영자는 기존 열린 탭을 새로고침하고 이전 직접 발급 코드를 종료해야 한다. 발급 선점 이후 현장 변경과 외부 업체 접수는 하나의 DB 트랜잭션으로 묶을 수 없으므로 발송 중 관련 회원 일괄 수정은 피한다.

## 검증과 복구

API 격리 테스트는 동시 실행·정확한 명단·쓰기 없는 dryRun·현장 변경·권한·브랜드·응답 유실·영수증 오류를 확인한다. 실제 네트워크가 없는 PostgreSQL 두 세션에서 행 잠금·원자성·고유 선점·역할 권한을 검증한다. 사용자의 실제 접수·수신은 합성 테스트로 대체하지 않는다.

선점 후에는 DB 테이블/행을 삭제하거나 이전 코드를 복원해 자동 재발송하지 않는다. 먼저 해당 대상의 발송을 보류하고 업체 영수증을 대조한다. 코드 복구가 필요해도 선점과 영수증을 보존하고 같은 방어선을 유지하는 수정으로 진행한다. DB 설치 실패 시 전체 트랜잭션을 롤백하고 기존 발송 보류를 유지한다.
