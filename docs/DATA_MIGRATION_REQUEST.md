# 기존 사이트 → 통합전산 데이터 이관 요청서

> 대상 사이트: **크로바 · 일행 · 88 · 프리미엄 · 815** (5개)
> 목적: 각 사이트의 회원 DB와 운영 정보를 통합전산(플러스로또 운영 콘솔)으로 이관
> 작성 근거: 통합전산이 실제로 저장·활용하는 항목(`docs/`·`src/types/db.ts` 스키마) 기준으로 역산
> 요청일: 2026-08-05 (현장 요청 — 김형준 이사)

---

## 0. 이전 업체에 보내기 전 — 3줄 요약

1. **가공하지 말고 원본 그대로 주십시오.** 업체가 임의로 우리 형식에 맞춰 변환하면 정보가 유실됩니다. 원본 테이블 덤프 + **코드값 설명서(코드북)** 조합이 가장 안전합니다.
2. **가장 중요한 3가지**: ① 회원 기본정보(전화번호 필수) ② **유료회원 이용기간 종료일** ③ 담당자 배정 현황. 이 셋이 없으면 이관 후 영업·서비스가 즉시 끊깁니다.
3. **샘플 먼저**: 전량 전에 사이트당 100건 샘플을 받아 매핑을 확정한 뒤 전량을 받습니다. (전량부터 받으면 형식 오류 발견 시 전부 다시 받아야 합니다.)

## 1. 필수 요청 자료 (없으면 이관 불가)

### 1-3. 담당자(상담원) 목록 `staff`

| 요청 항목 | 필수 |
|---|---|
| 상담원 고유번호 / 로그인ID | ★필수 |
| 이름 | ★필수 |
| 직급·역할 (실장/팀장/담당 등) | ★필수 |
| 소속 팀명 | ★필수 |
| 재직 여부 (퇴사자 포함 여부 표시) | ★필수 |

> 회원·결제 파일의 "담당자" 값을 신규 전산 계정과 연결하려면 이 매핑표가 반드시 필요합니다. **퇴사자도 포함**해 주십시오 — 과거 결제의 매출 귀속이 깨집니다.

### 1-4. 코드값 설명서 (코드북) — **필수**

각 파일에 쓰인 **모든 코드값의 의미 목록**입니다. 예:

```
회원등급:  1=간편가입, 2=무료, 3=골드, 4=실버, 5=다이아 …
회원상태:  A=정상, S=정지, D=삭제, W=탈퇴
결제상태:  0=대기, 1=승인, 2=실패, 9=취소
유입구분:  N=신규, O=구DB …
```

> 이게 없으면 숫자·영문 코드의 의미를 추측해야 하고, 등급을 잘못 매핑하면 **무료회원에게 유료 서비스가 나가거나 그 반대**가 됩니다.

## 2. 권장 요청 자료 (있으면 영업 연속성이 크게 좋아짐)

### 2-1. 상담 메모 / 콜 이력
- 회원 고유번호, 작성일시, 작성자(상담원), 메모 내용, 작성 당시 상담상태
- → 통합전산의 회원상세 "메모 이력"으로 이관. **없으면 상담원이 고객 히스토리를 잃습니다.**

### 2-2. 발급 번호(추천 조합) 이력
- 회원 고유번호, 회차, 발급일시, 발급된 번호 조합(6개 숫자 × N세트)
- → 고객 홈페이지 "내 발급번호 조회"와 당첨 집계에 사용

### 2-3. 당첨 이력
- 회원 고유번호, 회차, 등수, 당첨금액, 당첨 조합
- → 당첨자 세그먼트·당첨 안내문자 대상 산정

### 2-4. 문자 발송 이력
- 회원 고유번호, 발송일시, 발송유형(가입/추천/당첨/광고), 발송 내용, 발송 결과
- → 회원상세 문자내역. 최소 **최근 6개월분**만이라도 요청

### 2-5. 상품 목록
- 상품명, 가격, 이용개월수, 부여등급, 판매중단 여부

### 2-6. 통화 녹음 파일
- 파일 + **파일명↔회원/통화일시 매핑표** (매핑표 없는 녹음은 사실상 사용 불가)
- 용량이 크므로 **보관 기간·총 용량 먼저 문의** 후 범위 결정

## 3. 공통 형식 규칙 (업체에 그대로 전달)

| 항목 | 요청 형식 |
|---|---|
| 파일 형식 | CSV(권장) 또는 Excel(.xlsx). DB 덤프 가능하면 더 좋음(`.sql`/`.dump`) |
| 문자 인코딩 | **UTF-8** (한글 깨짐 방지). 불가 시 CP949/EUC-KR 명시 |
| 첫 행 | 컬럼명(헤더) 포함 |
| 날짜/시각 | `YYYY-MM-DD HH:MM:SS` (시간대: 한국시간 기준인지 명시) |
| 전화번호 | 원본 그대로. **임의로 하이픈 제거·앞 0 삭제 금지** (엑셀에서 `01012345678`이 `1012345678`로 깨지는 사고 빈번 → 텍스트 서식으로) |
| 금액 | 숫자만 (쉼표·원 표기 없이) |
| 빈 값 | 공란 유지 (`NULL`·`-`·`0` 등으로 임의 치환 금지) |
| 파일 분할 | 사이트별로 **파일 분리** (크로바/일행/88/프리미엄/815) — 합쳐서 주면 출처 구분 불가 |
| 건수 확인 | 각 파일의 **총 건수를 별도로 기재** (전송 중 유실 검증용) |
| 전달 방식 | 암호 걸린 압축파일 + **비밀번호는 다른 경로**(문자/전화)로 전달 |

## 4. 개인정보 관련 (반드시 함께 요청)

1. **개인정보 처리방침 / 마케팅 수신동의 이력** — 이관 후 문자 발송의 적법 근거
2. **개인정보 이전에 대한 근거 서류** — 영업양도·위탁 계약서 등, 정보주체 통지 이력
3. **이관 완료 후 원본 파기 확인서** — 업체 보관분 파기
4. 전달 담당자 지정 — 양측 1명씩(질의응답 창구 단일화)

> 개인정보가 대량 포함된 이관이라, 위 서류는 나중에 문제 되기 전에 처음부터 받아두는 편이 안전합니다. (법률 자문이 필요한 부분은 별도 확인 권장)

## 6. 운영진 결정 필요 사항 (업체가 아니라 우리 내부 결정)

5개 사이트를 하나로 합치면 아래는 **정책 결정**이 필요합니다. 업체 회신 전에 미리 정해두면 이관이 빨라집니다.

1. **같은 사람이 여러 사이트에 있을 때(전화번호 중복)**
   - 하나로 합칠 것인가, 사이트별로 별도 회원으로 둘 것인가?
   - 합친다면 등급·담당자·이용기간은 어느 쪽 기준인가? (예: 등급이 높은 쪽 / 최신 결제 기준)
2. **담당자 배정 승계** — 기존 담당자를 그대로 이어받을지, 통합 후 재배분할지
3. **유료회원 잔여기간** — 남은 기간을 그대로 인정할지, 별도 정책을 적용할지
4. **이관 범위** — 탈퇴/삭제 회원, 수년 전 비활동 회원도 가져올지 (개인정보 최소보유 관점에서는 제외 권장)
5. **통합전산 등급 체계 매핑** — 5개 사이트의 등급을 통합전산 8등급(간편가입·무료·골드·골드플러스·VIP·로얄·인반언스·토스DB) 중 무엇으로 볼지

## 7. 참고 — 통합전산 현재 수용 능력

- **회원 일괄 등록**: 전산 `이용자 > 일괄 임포트`에서 엑셀/CSV 업로드 지원 (이름·휴대폰·유입코드·유입구분·상담상태·성향·닉네임·메모 매핑). 전화번호 중복은 자동 차단되고 기존 회원이 '중복 DB'로 표시됩니다.
- **결제·발급번호·문자 이력**은 현재 화면 업로드 기능이 없어 **개발팀 직접 적재**가 필요합니다(1회성 스크립트). 자료만 확보되면 작업 가능합니다.
- 회원 규모 15만 기준으로 설계돼 있어, 5개 사이트 합산 물량은 성능상 문제 없습니다.
