# 같은 회차의 명시적 수동 추가 발급

## 동작

회원 상세의 지금 발급은 수량과 문자 발송 여부를 확인한 뒤 별도 요청 번호(UUID)로 추가 발급한다. 기존 자동발급·수동 이력을 보존하고 새 이력을 덧붙인다. 자동발급과 선택/등급 일괄 발급은 기존 회원·회차당 1회 규칙을 유지한다. 새 수동 추가 발급 이력이 자동발급 1회를 대체하지 않는다. 이전 버전의 원장/이력은 원래 중복 차단 의미를 유지한다.

요청 번호는 회원·운영자·수량·문자 여부에 결합된다. 더블 클릭, 동일 요청 재전달, 재로그인 또는 새로고침은 추가 문자를 만들지 않는다. 브라우저에는 전화/본문 없이 미확인 요청 정보만 보관한다. 확인된 접수 또는 문자 없는 발급, 서버의 명시적인 미발급 거절 기록만 다음 작업을 허용한다. 기록을 못 찾았다는 응답은 늦게 도착하는 요청을 배제하지 못하므로 새 요청을 허용하지 않는다.

회원 상태·기간·이관 보류·등록 발신번호·권한은 서버와 DB에서 재확인한다. 미확정/거절 문자 접수가 있으면 새로운 UUID를 사용해도 추가 발급을 막는다. 기존 수신 N에 대한 개별 현장 동의는 별도 전환 절차의 근거이며 원본을 덮어쓰거나 전체 수동 발급의 동의 우회로 사용하지 않는다.

## 이력과 집계

발급원장은 자동/기존 처리의 회원·회차 유일성과 새 수동 요청 UUID 유일성을 별도로 보장한다. 초기화·화면 이력 삭제는 접수 영수증이나 영속 원장을 지우지 않는다. 삭제/초기화된 수동 이력은 정확한 요청 번호로 구분하여 복원을 차단한다. 새 수동 발급은 기존 번호를 되살리는 대신 새 원장과 이력을 만든다.

당첨 집계는 같은 회차의 모든 활성 발급을 읽고, 요청별 조합 식별자를 보관한다. 발급·초기화·집계는 같은 잠금 순서를 사용한다. 등급 일괄 발급도 서버 선점 경로를 사용하며 브라우저에서 회원 meta를 덮어쓰지 않는다. 이 경로의 감사 증거는 회원별 발급원장/로그이며 기존 클라이언트 생성 요약을 새로 작성하지 않는다.

기존 원장 없는 legacy 카드의 화면 삭제 후 오래된 탭이 그 카드를 복원하는 기존 표시 제한은 남아 있다. 삭제 시 영속 차단 기록을 남겨 이를 새 자동발송 사유로 사용하지 않는다.

## 배포와 검증

`20261006133000_manual_additional_reco.sql` 다음 `20261006140000_manual_reco_history_consumers.sql` 순으로 동일 트랜잭션에 적용한다. 변경 전 함수 정의·ACL·인덱스·제약을 비공개로 백업하고 함수 해시를 다시 대조한다. DB 적용 후 앱을 배포한다. 이전 앱의 UUID 없는 요청은 이전 규칙으로 동작한다.

검증은 합성 회원을 사용한 PostgreSQL 트랜잭션·동시성·권한·삭제/초기화·당첨 집계, API 업체 응답 유실, 프런트 요청 복구, TypeScript와 빌드를 포함한다. 운영 고객 발급/문자/초기화는 QA에 사용하지 않는다. 실제 배포 상태와 현장 단말 수신은 테스트 통과와 구분해 비공개 인계에 기록한다.

되돌릴 때 신규 발급원장 또는 영수증을 삭제하거나 이전 단일 유일 제약으로 되돌리지 않는다. 이미 새 수동 발급이 있다면 데이터를 보존한 전진 수정 또는 추가 UI의 임시 중단으로 처리한다. Plus와 88은 코드·DB·배포 증거를 각각 관리한다.
