# 플러스로또 추천조합 생성 로직 — 전산 구현 현황

> 작성: 2026-06-23 / 대상: 조합생성 로직 검증
> 제공해주신 「제외수 프로그램」 방식이 전산에 어떻게 구현·적용되어 있는지 1:1로 정리한 문서입니다.
> 구현 원본(단일 출처): `src/lib/lottoGenerator.ts`(순수 로직), `src/lib/lotto.ts`(고정/제외·당첨판정),
> 자동발급 크론 `api/weekly-reco.ts`(동일 로직 인라인 사본).

## 0. 한눈에 보기

```
대상회차 = 최신 회차 + 1 ,  추첨월 = 직전 회차의 추첨월
        │
 ① 제외수 산정  ──  5개 규칙으로 후보 수집 → 10/15/20개로 "압축" → 운영자 수동제외 병합
        │
 ② 풀 구성     ──  남은 풀 = 45 − 제외수   (운영자 고정수는 항상 포함, 제외 안 함)
        │
 ③ 조합 생성   ──  풀에서 "품질 필터" 통과하는 6개 조합을 N세트
        │
 ④ 로직:랜덤   ──  발급 시 N조합 = 로직조합(비율%) + 완전랜덤(나머지)   ※ 기본 100% 로직
```

- 제공하신 규칙(직전회차·보너스·월별 저출현·저빈도·40번대 과출현 + 압축필터 + 극단조합 회피)이
  **그대로** 구현되어 있습니다.
- 회원이 **실제 받는 발급 조합**은 모든 경로(주간 자동발급·수동발급·일괄설정)가 **동일한 엔진**을 공유합니다.

## 1. 제외수 5규칙 (코드: `computeExclusions`)

각 후보 번호에 **우선순위(priority)** 를 부여해 모은 뒤, 번호별 최상위 사유만 남기고
**우선순위 내림차순으로 상위 N개(=제외수 개수)** 만 채택("압축")합니다.

| # | 규칙 | 구현 내용 | 우선순위 |
|---|---|---|---|
| ① | **직전회차 상·하위** | 직전 당첨 6개 중 **최상위 2개 + 최하위 1개 = 3개** | 100 |
| ② | **직전 보너스** | 직전회차 **보너스 1개** | 95 |
| ③ | **월별 저출현** | **대상 추첨월**에 역대 출현이 가장 적은 번호 (동률은 전체 저빈도순) | 80 |
| ④ | **회차 저빈도** | 전체 역대 출현이 적은 번호. **대상 회차가 10의 배수면 우선순위 +5 가중** | 70(+5) |
| ⑤ | **40번대 과출현** | 최근 20회차 기준 **40~45 중 많이 나온 2개** (과편입 회피) | 60 |
| + | **운영자 수동 제외** | `설정 > 로또 고정/제외`의 제외수는 **압축 한도와 무관하게 항상 포함** | — |

**압축 할당표(제외수 개수별 ③·④ 배분)** — ①직전3 + ②보너스1 은 공통, 나머지를 ③월별·④빈도에 배분:

| 제외수 개수 | ③ 월별 | ④ 빈도 | 합계 |
|---|---|---|---|
| 10개 | 4 | 4 | 3+1+4+4 → 상위 **10** |
| 15개 | 5 | 6 | 3+1+5+6 → 상위 **15** |
| 20개 | 7 | 7 | 3+1+7+7 → 상위 **20** |

> ⚙️ **실제 발급은 항상 "제외수 20개" 기준**으로 동작합니다(회원이 받는 조합). 10/15/20 선택은 운영자 탐색 화면(추천번호 페이지)에서만 조정합니다.

## 2. 조합 품질 필터 (코드: `passesQuality`) — 극단조합 회피

풀(45 − 제외수)에서 무작위로 6개를 뽑되, **아래를 모두 통과한 조합만** 채택합니다.

1. **역대 1등 동일 조합 회피** — 과거 당첨번호와 똑같은 조합 제외
2. **구간 분산** — 1–9 / 10–19 / 20–29 / 30–39 / 40–45 중 **최소 3개 구간**에 분포
3. **한 구간 몰림 금지** — 한 구간에 **4개 이상** 몰리면 제외 (예: 40번대만 4개)
4. **전홀/전짝 금지** — 6개가 모두 홀수 또는 모두 짝수면 제외
5. **연번 제한** — **3연속 이상 금지**, 연속쌍(2연속)은 **최대 1쌍**
6. **합계 밴드** — 6개 합이 **역대 당첨합의 10~90분위 범위** 안 (데이터 부족 시 100~175)

> 풀이 너무 좁아 6개를 못 만들면 자동으로 **완화 모드**(구간 5개 몰림·6연번만 차단)로 재시도합니다.

---

## 3. 고정수 / 제외수 입력 (운영자 · 등급별 · 효력일자)

코드: `resolveExcludeForGrade` (`설정 > 로또 고정/제외` 화면과 연동)

- **고정수**: 지정한 번호는 **모든 조합에 항상 포함**(통계 규칙으로도 제외되지 않음).
- **제외수**: 지정한 번호는 **항상 제외**.
- **등급별 규칙 + 효력일자**: 토요일에 입력하면 **익주 월요일(effective_from)부터 적용**.
  현재 등급별 규칙 운영 등급은 **골드·VIP·로얄** 3등급이며, 그 외 등급(골드플러스 포함)은 **공통(전체) 규칙**을 따릅니다.
- 풀이 6개 미만이 되도록 제외가 과하면, **우선순위 낮은 통계 제외부터 자동 복원**(수동 제외는 유지)해 항상 6개 조합이 가능하도록 방어합니다.

## 4. 로직 : 랜덤 비율 (코드: `generateIssueSets`)

발급 N조합 = **로직 조합** + **완전 랜덤 조합** 을 비율로 혼합합니다.

- 비율(`로직 적용 비율 %`)은 `설정 > 로또 고정/제외`에서 조정. **기본값 100%(전부 로직 조합)**.
- 예) 10조합·비율 70% → 로직 7 + 랜덤 3.
- 랜덤분은 제외수·품질필터를 적용하지 않는 완전 무작위이며, **로직 조합과의 중복만 회피**합니다.
- **현재 운영 설정값: 비율 100%** → 지금 발급되는 조합은 **전부 위 1~3의 로직 조합**입니다.

## 5. 발급 경로 (모두 동일 엔진 공유)

| 경로 | 동작 |
|---|---|
| **주간 자동발급(크론)** | 매일 09:00, 회원별 **발송요일**이 오늘인 회원에게 **조합발송갯수**만큼 발급 → 회원 홈페이지에서 조회 |
| **수동 발급** | 회원 상세에서 즉시 발급 |
| **일괄 설정** | 이용자 일괄작업 → "자동조합"으로 다수 회원의 발송요일·조합수 일괄 지정 |

> 유료(골드~로얄) 회원은 **발송요일을 지정해야** 자동발급 대상이 됩니다. 발급 조합 수는 회원별 설정값(없으면 전역 기본 30)을 따릅니다.

## 6. 확률 정직성 (중요 — 코드 주석에도 명시)

- 6/45에서 **모든 6개 조합의 1등 확률은 1/8,145,060 로 동일**합니다.
- 본 엔진은 제외수·품질 기준으로 **"제시할 조합을 선별·압축"** 할 뿐이며, **어떤 조합의 당첨 확률을 실제로 높이지 않습니다.**
- 따라서 전산은 "확률이 N배 증가"를 사실로 단언하지 않습니다(코드·반환값 어디에도 확률 향상 주장 없음). 제공 로직의 **선별 기준은 100% 반영**하되, 확률 과장만 배제한 구현입니다.
