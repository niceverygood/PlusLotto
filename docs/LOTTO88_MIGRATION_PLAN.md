## 3. 지켜야 할 것

- 원본 덤프·운영 DB의 실명·전화번호·결제이력은 **개발 컨테이너에 올리지 않는다**.
  이관 도구는 대표님 로컬에서 실행하고, 결과는 PII 없는 건수만 공유한다.
- `--apply` 에는 **항상 `--batch-id`** 를 붙인다. 없으면 롤백이 불가능하다.
- 등급표를 임의로 채우지 않는다. 88로또는 스키마가 같아 추정할 일이 없어야 정상이다.
- `reco_paused` 를 일괄 해제하지 않는다. 전환 시 발송 대상 활성화는 명시적 절차로만.

## 4. 신규 요구 — 전 사이트 도메인 이전 + 사이트별 회원 홈페이지 (9/21)

> "88로또 포함 전 사이트 도메인 이전 예정이며, 모든 사이트 회원용 홈페이지 전산과 연동시킬수
> 있도록 **새로운 회원용 홈페이지 작성** 부탁드리겠습니다." (정의현 차장 9/21)

### 지금 있는 것

루트(`/`)에 고객 홈페이지가 **이미 9개 화면**으로 돌아간다 — 홈 · 시스템 · 자료 · 멤버십 ·
마이페이지 · 로그인 · 가입 · 고객센터 · 약관. 사이트별 로그인(`sourceSite`)도 지원한다.

### 진짜 막히는 지점

`src/features/site/*` 7개 파일이 브랜드명을 **빌드 시점 상수 `BRAND`**(`VITE_BRAND`, 배포 단위)로
표시한다(총 28곳). 한 배포 = 한 브랜드이므로, **815 회원이 815 도메인으로 들어와도 화면에는
"플러스로또"가 뜬다.** 문자 본문에서 `$brand` 로 고친 것과 같은 문제의 홈페이지 판이다.

### 그래서 필요한 것 — "새로 작성"이 아니라 "도메인별 전환"

1. 런타임 사이트 판별 (hostname → 사이트 키). `BRAND` 는 빌드 상수라 이 역할을 못 한다.
2. `src/features/site/*` 의 `BRAND` 사용 28곳을 런타임 값으로 교체.
3. 사이트별로 달라야 하는 내용 분리 — 상호·사업자정보, 멤버십 등급·가격, 약관, 고객센터 연락처.
4. 로그인에서 사이트 선택 드롭다운 제거 가능 — 도메인이 곧 사이트가 된다.
5. Vercel 도메인 연결 (사이트 수만큼).

기존 9개 화면을 버리고 다시 만들 이유는 없다. 다만 **현장이 말한 "새로운"이 디자인 신규 제작을
뜻하는지**는 확인이 필요하다 — 확인 전까지 위 해석으로 적어 둔다.

### 일정 — 88로또 데이터 전환과 분리할 것

**10/5 전환에 얹지 않는다.** 데이터 이전과 도메인·홈페이지 전환을 같은 날 하면, 문제가 생겼을 때
어느 쪽 탓인지 구분이 안 된다. 10/6 화요일 발송까지 안정화한 뒤 별도 일정으로 잡는다.
도메인 이전 시점은 현장 확인 필요.

### 확인 필요

- "새로운 회원용 홈페이지"가 **디자인 신규 제작**인지, 지금 화면의 **사이트별 전환**인지
- 사이트마다 내용이 달라야 하는 범위 (멤버십 가격·약관·사업자정보가 사이트별로 다른가)
- 도메인 이전 희망 시점
