# 815 이전 전산 이력 조회

815 회원 상세에 이전 전산 이력 탭을 추가한다. 상담메모·문자기록·당첨기록을 회원별 50건씩 조회하며 다음 페이지, 로딩, 빈 결과와 재시도 상태를 제공한다. 원본 시각과 금액을 보존하고, 보관 정책상 제외된 문자 본문은 별도 안내로 표시한다.

읽기는 TanStack Query 훅과 SECURITY INVOKER RPC를 사용한다. 기존 운영자 역할 및 회원 담당/팀 범위를 DB RLS로 검사하며 비공개 메모는 추가로 제한한다. 공식 Supabase 생성 타입과 런타임 응답 검증을 함께 사용한다.

검수 보류 회원은 수동 추천과 SMS 벤더 호출 전에 차단한다. 보류 확인에 실패하거나 설정이 누락되면 발송하지 않는다. 발송 없이 보류 여부만 확인하는 요청도 제공한다. 이 배포는 발송 보류를 해제하거나 고객 이관을 실행하지 않는다.

## 배포 순서

1. 대상 환경의 마이그레이션 이력과 함수/테이블 정의를 비교한다. 이미 적용된 스키마 또는 완료된 이관 실행기를 재실행하지 않는다.
2. 대상 main의 최신 변경을 반영하고 PR의 타입 검사·빌드·TypeScript 회귀 테스트·메모리 DB 회귀 테스트를 확인한다.
3. Vercel Preview에서 관리자 로그인, 815 사이트 선택, 이전 이력 탭의 세 종류와 다음 페이지를 확인한다. 다른 회원으로 이동할 때 내용이 갱신되고 허용되지 않은 역할에는 데이터가 보이지 않아야 한다.
4. main 병합 뒤 Vercel Production의 소스 커밋과 Ready 상태를 확인한다. 운영 도메인이 해당 배포를 가리키는지, 이전 이력 조회와 발송 보류가 실제 환경에서도 유지되는지 확인한다.

## 복구 기준

다른 회원의 이력 노출, 권한 경계 위반, 정상적인 이력 조회 실패 또는 발송 보류 실패가 발생하면 운영 노출을 중단한다. 새 화면만 문제라면 검증된 이전 프런트엔드로 복구하되 발송 보류 서버 로직과 DB 보호가 함께 유지되는 버전을 사용한다. 보류 보호 이전 버전을 무조건 승격하지 않는다. 이력 테이블과 적재 데이터는 삭제하지 않는다.

로컬 검증과 운영 배포 검증은 별개다. 실제 배포 커밋·URL·확인 시각은 운영 반영 이후 기록한다.
