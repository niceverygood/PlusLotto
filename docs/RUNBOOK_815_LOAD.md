## 왜 이 순서인가 — 8/31에 무슨 일이 있었는지

그날 **데이터는 정상적으로 들어갔다.** 회원 19,829명, 결제 25,679건 모두 변환이 맞았다.
문제는 **들어갈 자리가 없었다**는 것이다.

그때 전산에서 사이트를 구분해 보여주는 곳은 **회원목록 한 군데뿐**이었다.

| 화면 | 8/31 당시 | 지금 (PR #42 이후) |
|---|---|---|
| 회원목록 | 있음 | 있음 |
| 결제 관리 | **없음** | 있음 |
| 매출 | **없음** | 있음 |
| 대시보드 | **없음** | 있음 |
| 통계 | **없음** | 있음 |

그래서 815 데이터가 들어가는 순간 대시보드 신규유입이 뛰고, 결제 목록에 815 결제가 섞이고,
매출에 134억이 얹혔다. 정의현 차장이 본 "전산 이상합니다"가 이것이다.
**로더 버그가 아니라, 칸막이 없는 방에 손님을 들여보낸 것이다.**

9/1에 차장이 요구한 것도 정확히 이것이었다.

> "각각 88/815/일행 등 사이트별 독립적 대표번호부터 다릅니다.
> **회원들이 섞이면 안 되어서** 개별 사이트별로 관리할 수 있게 요청 드립니다.
> 전달드린 디비를 **사이트별로 드롭다운 클릭하면** 사이트별 관리할 수 있게 요청 드립니다."

**이 요구는 PR #42로 충족됐다.** 그래서 이제 1단계(검증)만 마치면 3단계(적재)로 갈 수 있다.

# 2단계 — 사이트 구분 (✅ 9/9 완료)

PR #42로 완료됐다. 아래는 3단계 확인 때 무엇을 보면 되는지 알기 위한 요약이다.

- 상단 **`관리 사이트`** 에서 플러스로또·815로또·인포로또·일행로또·전체 사이트를 고른다.
  처음 들어가면 **플러스로또**가 선택돼 있다.
- 회원, 나의고객, 나의 문자내역, 결제, 대시보드, 매출·캘린더·일일요약, 통계·상담통계에
  같은 사이트 범위가 걸린다. 새로고침·뒤로가기·URL 공유에도 `?site=` 로 따라간다.
- `source_site` 가 없거나 빈 기존 회원은 **플러스로또**로 본다. 기존 행을 일괄 수정하지 않았다.
- 결제는 **연결된 회원의 출처**를 따른다. 수기 결제도 그 회원의 사이트로 귀속된다.
- 관리자·설정·상품·문자 템플릿·로그·베팅·급여는 공통 관리다. 상단에 `공통 관리`로 표시되고
  사이트 선택이 비활성화된다.

> ⚠️ **아직 안 된 것 — 브랜드별 문자 경로.**
> 발신번호·문자 템플릿·가입환영 문자는 **여전히 공통**이다. 815 회원에게 문자를 보내면
> 플러스로또 발신번호로 나간다. 815 회원의 **결제 승인과 문자 운영을 실제로 시작하기 전에**
> 이 경로를 분리해야 한다. 적재 자체를 막는 문제는 아니지만, 적재 후 발송을 켜기 전에 반드시 해결한다.

> ⚠️ **`reco_paused` 의 범위를 오해하지 말 것.**
> 이 값은 **조합 발급과 추천문자만** 보류한다. 가입환영·당첨안내 등 다른 종류의 문자까지
> 막는 스위치가 아니다. 적재 직후 모든 문자를 확실히 막으려면 아래 3-6의 전역 스위치를 쓴다.

# 문제가 생겼을 때

## 되돌리기

배치 키로 이번에 넣은 것만 정확히 지운다. **결제를 먼저, 회원을 나중에** 지운다
(순서가 바뀌면 참조 오류가 난다).

```sql
-- 1) 지우기 전에 반드시 건수부터 센다
select count(*) from payments where meta->>'import_batch' = 'lotto815-20260909';
select count(*) from members  where meta->>'import_batch' = 'lotto815-20260909';

-- 2) 건수가 예상과 맞을 때만 실행
begin;
delete from payments where meta->>'import_batch' = 'lotto815-20260909';
delete from members  where meta->>'import_batch' = 'lotto815-20260909';
-- 여기서 다시 세어 보고, 맞으면 commit / 이상하면 rollback
commit;
```

## 문자가 나갈까 걱정될 때

적재된 회원은 `meta.reco_paused = true`로 들어간다(로더가 자동으로 넣는다).
**다만 이 값은 조합 발급과 추천문자만 막는다.** 가입환영·당첨안내 등 다른 문자까지 막는
스위치가 아니다. 모든 문자를 확실히 막으려면 **설정에서 전역 스위치를 내린다.**

- 설정 → 조합 자동발급 `weekly_free_reco.enabled` → 끔
- 설정 → 유료회원 조합문자 `paid_sms` → 끔

현장 검수가 끝나고 대표 승인을 받은 뒤에 다시 켠다(D178과 같은 절차).
**켜기 전에 브랜드별 발신번호·템플릿 분리가 됐는지 먼저 확인한다.** 지금은 공통이라
815 회원에게 플러스로또 발신번호로 문자가 나간다.
